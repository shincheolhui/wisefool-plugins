# 기록의 소재를 어댑터로 위임 + 사고 기록 조항 신설

- 이슈: [#3](https://github.com/shincheolhui/wisefool-plugins/issues/3)
- 브랜치: `feature/3-knowledge-locations`
- 상태: 진행 중

## 배경

정본이 기록 종류마다 **소재를 하드코딩**하고 있다.

| 조항 | 남기는 것 | 정본이 못박은 소재 |
|---|---|---|
| 2.4 | 설계 결정·막힘 | 이슈 댓글 |
| 3.6 | 교훈 | "메모리·문서" (모호) |
| 1.5 | 계획·spec | **디렉토리** (저장소 경로 전제) |

그런데 이슈를 관리하는 지점과 지식을 쌓는 지점은 프로젝트마다 다르다 — GitHub Issues + Wiki,
Jira + Confluence, 전부 저장소 안. #2 에서 추가한 `Plan location` 이 *"The **directory** where
spec and plan documents are kept"* 라고 저장소 경로를 전제해 버려, 계획을 Confluence 에 두는
팀은 표현할 방법이 없다. 하루 만에 한계에 걸렸다.

소재 선택은 취향이 아니라 두 가지가 결정하는 **원칙 있는 차이**다:

- **청중** — 개발자만 읽으면 저장소(코드 옆, 리뷰에 걸림), 비개발자도 읽어야 하면 Wiki·Confluence
- **버전 관리 필요성** — 코드와 함께 되감겨야 하는 지식은 저장소, 시점 스냅샷이면 되는 지식은 밖

## 목표

정본은 **무엇을 어떤 조건에서 남길지**만 정하고, **어디에 남길지는 어댑터가** 답한다.

## 방침

### 1. 어댑터 키 `Plan location` → `Knowledge locations` 흡수

기록 종류별 소재를 프로젝트가 선언한다. 소재는 저장소 경로일 수도, 위키·Confluence 공간일
수도, 트래커 자신일 수도 있다.

**폴백 체인:** 종류별 선언 → 없으면 이슈(트래커) → 트래커도 없으면 Todo·보고.
어느 경우에도 **프로젝트에 디렉토리를 임의로 만들지 않는다.**

**호환:** 1.2.0 의 `Plan location: <경로>` 표기는 계획 항목 선언으로 계속 인정한다.
한 줄 단서로 파괴적 변경을 피한다 (이 저장소 `CLAUDE.md` 도 그 표기를 쓰고 있어 그대로 동작).

### 2. 1.5 의 저장소 경로 전제 제거

"워크트리 안에서 작성·커밋"은 **소재가 저장소 경로일 때만** 적용되도록 조건화한다.
외부 시스템이면 거기에 생성한다.

### 3. §3 에 사고 기록 조항 신설

**트리거(객관적):** 버그·설정 오류·운영 실수로 **실제 피해가 발생한** 작업 — 잘못된 결과가
사용자·외부에 도달, 데이터 손상·유실, 서비스 중단, 수동 개입이 필요했던 경우.
*발생할 뻔한 것(near miss)은 제외* — 그건 교훈 기록의 몫이다.

**템플릿:** `증상 → 원인 → 해결 → 재발 방지 → 관련 자산(이슈·커밋·정본 문서 링크)`.
비개발자 용어로 쓰고, 정본 문서는 링크로 위임한다(중복 서술 금지).

**노이즈 금지:** 일반 기능·리팩토링 작업은 대상이 아니다. 원본 정본이 같은 단서를 달았다.

**연결:** 기록을 이슈에서 링크해 역추적 가능하게 한다.

이후 항목 재번호 (3.6 교훈 → 3.7, 3.7 워크트리 정리 → 3.8), 체크리스트 반영.
